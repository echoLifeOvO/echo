## 组织方式

使用 `<方向>/<主题>/README.md` 作为主题入口，例如未来确实学习某概念时再创建相应路径。主题变长后再拆成理解笔记、来源、实验、未解问题等子文档；目录名简短稳定，标题可以用中文。

一篇主题文档可以按需写下：

- 起点：为什么感兴趣，最初想问什么。
- 当前理解：关键概念、推理、例子，哪些已验证、哪些只是猜想。
- 我的想法：用户自己的判断、联系或认识变化；AI 建议单独注明。
- 依据：资料标题、作者、链接、访问日期，必要的章节或页码。
- 留下的问题：卡住之处、分歧和可能继续的方向。
- 相关产物：实验、代码、研究报告、视频与反馈的相对链接。
- 更新记录：有意义的日期与认识修正。

这些是提示，不是每篇必填的表格。一个重要疑问也值得保存。优先维护已有笔记，跨方向建立链接。新增主题后在本页增加“方向 / 主题 / 当前状态 / 路径”，方向较多时再建立各自的索引。

## 留下下一次好奇的入口

每次探索除了留下当前理解，也可以按需留下：

- 没想明白的地方：略过的内容、仍不信服的解释、缺少的前置理解。
- 与已有探索的联系：新内容如何改变旧问题的理解，两个概念为什么值得比较，以及它们的差异和类比边界。
- 值得试一下的事情：一段原文、一个反例、小实验或想做的作品。

联系应指向具体文档或段落，并在两端各写一句说明、建立相对链接；避免仅因关键词相同就连接。未验证的联系标作“待验证”，后续查证后补充结果，包括联系不成立的原因。个人认识的重新组织也有价值，不必宣称是学术原创。

当用户不知道学什么时，从这些记录中选择少量线索，说明它来自哪次探索、为什么值得继续、可以从什么小入口开始。若历史记录不足，坦诚说明，不编造兴趣或经历。建议是邀请，不是课程安排；用户可以选择任何新方向。

暂不预建知识图谱或自动推荐系统。随着内容积累，再决定是否需要单独的连接索引或工具。
